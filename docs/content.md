## Происхождение данных

Основной источник — приложенные `PRESENTATION-CONTEXT.md`, `deck.src.html` и три изображения из `presentation-kit.zip`. Исходный контекст сохранён в [original-context.md](original-context.md) как исторический документ; инструкции о публикации в Claude к текущему репозиторию не относятся.

Данные прогона относятся к **12.11.2026**. Полные `06-test-runs.html`, `08-presentation.html` и исходный экспорт переписки не были приложены. Новый прогон продукта не проводился. Описания архитектуры, весов, нагрузочных замеров и разметка репозиториев перенесены из предоставленных материалов, а не подтверждены аудитом сервиса.

Первичный внешний источник для исправления формулировки про GitHub API: [GitHub Docs — List stargazers](https://docs.github.com/en/rest/activity/starring#list-stargazers), проверен 16.11.2026. Media type `application/vnd.github.star+json` поддерживает timestamp установки звезды. Поэтому тезис «GitHub API даёт только одну точку в сутки» заменён сравнением дневной агрегации и собственных снимков. Документация также описывает ограничения доступа; наличие токена само по себе не гарантирует доступ ко всем данным.

## Как трактовать результаты

- 5 репозиториев, отмеченных командой как накрутка, получили score ≥ 30.
- 9 органических проектов без вирусной волны получили score < 30.
- 2 органических проекта с вирусной волной получили ложные предупреждения.
- Всего органических проектов в выборке **11**, а не 9.
- Сравнение проводилось с тремя активными эвристиками. Три внутридневные проверки на этой выборке ещё не оценены.
- Независимая контрольная выборка в материалах не описана. Следующий шаг с такой оценкой — предложение переработки, не завершённый этап команды.
- Score не является вероятностью. Правило нормализации при недоступных проверках не раскрыто; из весов нельзя восстанавливать точную реализацию формулы.

Название `Adkid-Zephyr/anti-defensive…` оставлено сокращённым как в оригинале. Полное имя не выдумано. Кривые на слайдах 1, 2 и 7 — иллюстрации, а не дополнительная измеренная выборка. Дифф слайда 10 — пояснение логики, не исполняемый конфиг.

## Нагрузка

На основном слайде оставлены 500 / 270 / 65 секунд для 1 / 2 / 4 потоков. 65 секунд сопровождались отказами примерно половины запросов, поэтому не показаны как успешное ускорение полного опроса. Запас 2 потоков: 300 − 270 = 30 секунд.

В конфиге для сохранения контекста остаются 10 559 репозиториев, 1 300 запросов в час и заявленный лимит 5 000. Последние два числа убраны из слайда: архив не объясняет пакетирование, тип API и пересчёт лимита. Их нельзя интерпретировать как 10 559 отдельных REST-запросов каждые 5 минут при 1 300 запросах в час.
